# Licenses

Open source license templates.

## Files

- **`MIT`** — MIT License template
- **`Apache-2.0`** — Apache License 2.0 template
- **`GPL-3.0`** — GNU General Public License v3.0 template

## Usage

1. Copy the template to your project root as `LICENSE`
2. Replace `<year>` with the current year
3. Replace `<name>` with your name or organization

## Comparison

| | MIT | Apache-2.0 | GPL-3.0 |
|---|---|---|---|
| Commercial use | ✓ | ✓ | ✓ |
| Modification | ✓ | ✓ | ✓ |
| Distribution | ✓ | ✓ | ✓ |
| Private use | ✓ | ✓ | ✓ |
| Copyright notice required | ✓ | ✓ | ✓ |
| State changes required | — | ✓ | ✓ |
| Express patent grant | — | ✓ | ✓ |
| Trademark use denied | — | ✓ | — |
| Disclose source | — | — | ✓ |
| Same license required (copyleft) | — | — | ✓ |
| Warranty | none | none | none |

## About MIT

Permissive and short. Minimal restrictions — keep the copyright notice and you
can do almost anything, including relicensing under a proprietary license.

## About Apache-2.0

Permissive like MIT, plus an explicit patent grant from contributors and
protection against trademark misuse. Requires stating significant changes made
to the files. Preferred for larger projects and corporate contributions.

## About GPL-3.0

Strong copyleft. Anyone distributing the software (or derivative works) must
release the complete source under GPL-3.0 as well. Includes a patent grant and
anti-tivoization terms.

Note: GPL-3.0 code cannot be combined into proprietary software. Apache-2.0
code can be included in GPL-3.0 projects, but not the reverse.

## Applying the notice

`Apache-2.0` and `GPL-3.0` include an appendix describing a short per-file
header. Copy that boilerplate into your source files; the `LICENSE` file alone
holds the full terms.
